## 2. Feature context (self-contained recap)

`bore transfer web` creates no file selection: it prints a secret-fragment URL and keeps the room owner lease alive. Every browser peer with that link can announce local files/folders, see all peers' offers and explicitly download another peer's offer. Browser data uses one WebRTC DataChannel per transfer when possible, then an opaque bounded WebSocket relay fallback; both paths carry application AES-256-GCM ciphertext and the server stores no payload. Clean owner exit destroys immediately; abnormal disconnect allows authenticated resume for 60 seconds by default. Downloads never start or resume without a recipient click.

**Reference scenario:** A runs the CLI, opens its browser and announces a folder; B clicks and downloads it direct; C has ICE forced to fail and downloads through relay; B/C can publish too; B cancels a transfer; closing A's CLI invalidates room, URL and active transfers.
**Hard constraints:** preserve every `AGENTS.md` invariant and old wire fixture; append enum variants last; no new browser-data UDP socket/native QUIC; bounded buffers/maps/tasks/rates; no server payload storage; README updated at the end of every phase.
**Key decisions in force:**
- **D1:** CLI owns only the lease; all data sources/recipients are equal browser peers.
- **D2:** URL is `/transfer/<32hex>#m=<64hex>&k=<64hex>`; fragment secrets move to sessionStorage then are scrubbed.
- **D3:** recipient is fixed WebRTC SDP offerer, source answerer; one peer connection/data channel per logical transfer.
- **D4:** relay pairs two role-bound, one-use-ticket WebSockets and forwards one ciphertext frame at a time without storage.
- **D5:** server authority plus fresh AttemptId/derived key resolves direct/fallback/cancel races; source reads only after path_commit.
- **D6:** source-only serving; a recipient never swarms or republishes unless the user selects the local output explicitly.
- **D7:** manifest is immutable, canonical and HMAC-authenticated; 1 MiB SHA-256 chunks use the fixed rolling-root formula.
- **D8:** OPFS/IndexedDB hold verified partials but no token/key; cancel retains valid chunks, withdraw/room close purge them.
- **D9:** ZIP is per offer, store-mode streaming Zip64 via zip.js 2.15.0; no room-wide archive or full archive buffer.
- **D10:** service is enabled only by HTTPS `--web-transfer-base-url` (HTTP loopback allowed), on the existing control listener and exact Host.
- **D11:** all public defaults, caps, timeouts, error codes, flags and protocol bytes are fixed in `overview.md` and phase files; do not substitute alternatives.
- **D12:** implementation agent for every unit is `agent:gpt-5.6-luna`, with self-review before close.

## 9. Blockers and open questions

- ~~**Phase 3 cannot close before the serial SSH regression runs**~~ — run at 3.7 and green
  (gateway 42/0 in 273 s, spike 5/0). No blocker remains for phase 3.
- **Open (4.6): `direct / relay` has no two-host measurement.** On loopback the direct
  arm is bimodal and slower than the relay, and the relay arm is a localhost hop to a
  Rust server on the same machine — the most favourable condition a relay can have
  (V-9). Queue depth and the public STUN chain were both tested and falsified, so what
  is left is the transport itself, which a page cannot tune. 4.4 does **not** settle it:
  three browser contexts on one machine are the same loopback. Settling it needs two
  real hosts with a real path between them, which is an environment this plan has never
  had. Until it exists, `docs/transfer/WEB_TRANSFER_PERF.md` states the ratio as a
  property of the measurement and not of the product, and the README says the badge
  reports which path carried the bytes rather than which was faster.
- Otherwise none — the user accepted every proposed default; implementation must use the
  decisions in the plan without reopening them.

## 10. Do-not-repeat

- Do not ask the CLI to select or read paths; selection belongs to every browser peer.
- Do not reuse native QUIC/holepunch types for browser data or bind another UDP socket.
- Do not add HTTP upload, server file/temp storage, TURN, CDN assets, service workers, OS notifications or telemetry.
- Do not auto-download, auto-resume, auto-seed or create a room-wide ZIP.
- Do not use fflate or another ZIP library; the pinned implementation is `@zip.js/zip.js` 2.15.0.
- Do not move secret material from the URL fragment/sessionStorage into query, localStorage, IndexedDB, log or admin state.
- Do not use `timeout(recv)` for liveness or an unbounded heartbeat send; follow the tick/last_recv and `beat_once` invariants.
- Do not let async cleanup look up a current room by ID; capture the actual room through Arc/Weak plus epoch.
- Do not "fix" `cargo check --no-default-features`: broken pre-existing on clean tree (holepunch `Arc` import, verified via stash 14:54 CEST); plan gates use `--all-features`.
- Do not reintroduce `ring::constant_time`: deprecated in ring 0.17; digest comparison uses `subtle::ConstantTimeEq`.
- Do not `read_to_end` on a duplex without `shutdown`: the read side blocks forever (hung 2.1 suite 15 min; fixed by shutdown-after-write).
- Do not `pkill -f` with a pattern matching the workdir: it kills the tool's own shell wrapper (use `pgrep -af` to inspect, narrow patterns to kill).
- Do not e2e-force broadcast lag or queue eviction on loopback at control-message sizes: kernel buffers absorb any bucket-legal storm (prove resync/eviction bounds at unit level, reap at e2e).
- Do not rely on per-test `{ timeout }` details in Playwright here: it left the 30 s default in these runs; `test.setTimeout()` inside the body governs.
- Do not republish into a live ghost catalog: same-tab reconnects mint a new PeerId, so republish must partition (absent now, present on offer.removed) instead of racing OFFER_CHANGED.
- Do not send same-peer transfer events synchronously from the registry: return a `TransferOutbox` and drain it after the ack (ack-before-event, same FIFO queue).
- Do not gate on a parallel `web_transfer_test` run: the binary is serial-only (log-privacy dispatch); parallel flakes are suite violations, not product bugs.
- Do not emit `transfer.progress` on the wire in phase 3: the server accepts no such type (INVALID_MESSAGE); progress stays a local sender event until the recipient flow lands.
- Do not assert giant `deepEqual` diffs in JS tests: filter to the compared bytes first (a megabyte mismatch hangs the diff printer, not the code).
- Do not open a Playwright context with `browser.newContext()` for anything that touches OPFS: WebKit exposes `getDirectory` there and then throws `UnknownError`; use `openPersistentPeer` (a real on-disk profile) and assert the capability.
- Do not stage a download into one output file reopened with `keepExistingData`: every engine copies the whole output per chunk (quadratic — 128 MiB read 8.43 MiB/s against 22.81 at 32 MiB). Write one part file per chunk and compose a `Blob`.
- Do not index arriving chunks by arrival order: a resumed transfer skips verified ranges, so the position must come from the send plan.
- Do not `fetch()` an object URL from the page: its own CSP is `connect-src 'self'`, so the request is refused and the caller silently does nothing — keep the `Blob` and write it.
- Do not rebuild the catalog DOM inside a live event handler: a detached node loses the click (Playwright retries, then times out at 240 s). Gate the rebuild on a signature and update transfer rows in place.
- Do not send a stored size straight onto the wire: IndexedDB returns it as a decimal string and the server parses `as_u64`, so `outputLength` must be a `Number`.
- Do not key an error notice on `body.transferId`: `error_envelope_anon` carries the id in `message`.
- Do not assert a wire shape from a hand-written literal in a unit test: drive it from `tests/fixtures/web_transfer/v1/control-messages.json`, or the test passes against a shape the server never sends.
- Do not send a control message and exit: the yamux driver is a detached task, so the frame can die in its queue. Wait for the peer to drop the control (bounded) — a close that is not acknowledged did not happen.
- Do not let `bore transfer web` ride the generic `shutdown_signal()` race in `run()`: that race returns without closing the room.
- Do not trust a manifest that arrived through the server: verify its room-key tag before it enters the catalog AND again before the first `transfer.request`. The manifest carries the chunk digests and the entry root, so an unverified manifest makes every later per-chunk check verify against the forgery.
- Do not treat a post-ack 4001 as always healable: the server answers a dead room exactly as it answers a bad token, so an unbounded retry leaves the page saying "Riconnessione…" forever. One healing retry, then terminal.
- Do not close a socket locally with a code the SERVER also uses (the hello timeout now closes with 4002): a local timeout counted as a remote refusal strands a healthy session.
- Do not use `--web-transfer-owner-grace` below 5 s in a test: the server refuses it (`must be 5..=600s`) and the harness fails as "port never opened", which reads like a build problem.
- Do not build a fixture manifest with a made-up MAC: the recipient authenticates it now, so a constant tag tests the refusal path only. Compute the real tag from the fixture's own room key.
- Do not assert `starts_with(sandbox)` on a `/proc/<pid>/fd` target: a sibling path (`<sandbox>.log`) matches the prefix and the assertion fires on the test's own log. Compare against `<sandbox>/`.
- Do not put terminal output or a browser launch inside the owner lease: the lease has no way to order them against the print.
- Do not overwrite a text input from `render`: this app re-renders on every room event, so an unconditional assignment empties the field while the user types and submits stale text. Write it only when the element does not have the focus.
- Do not answer an unsupported shape with a "not found" code: a multi-entry offer is visibly in the catalog, so `OFFER_NOT_FOUND` sends the user hunting for a room problem. Say what is unsupported (`MULTI_ENTRY`).
- Do not red-check a browser fix by rebuilding `dist` alone: the server embeds the bundle at COMPILE time, so the page under test stays fixed and the check reports a false green. Rebuild the binary too.
- Do not assert an empty `failures` array after killing the room: closing the control socket makes WebKit log a page console error about the very close the next assertion requires. Snapshot the console state before the kill.
- Do not leave the page without a favicon reference: branded Chrome/Edge request `/favicon.ico`, the server answers 404 and every load logs a console error. `<link rel="icon" href="data:,">` costs no asset.
- Do not benchmark two arms in a fixed order: "first in the repetition" becomes a second variable and hands it to one arm. Alternate the order, then re-read the numbers.
- Do not add an asset without updating BOTH the exhaustive embedded-asset assertion (`src/web_transfer.rs`) and the served allow-list (`src/web_transfer_http.rs`): the first fails only in `--lib`, which the web-transfer suite alone does not run, and the second serves a 404 whose MIME makes the browser refuse the worker.
- Do not copy a chunk into a worker when the view owns its buffer: the structured clone is what turns this optimisation negative on webkit. Transfer it, and return it with a handled error so the fallback still has bytes.
- Do not publish a performance number an arm did not produce: `throughput_mib_s`/`throughputMiBs` return `None`/`null` on zero bytes or zero time and the report prints `median=FAILED`, which exits the driver nonzero (V-9).
- Do not print only a median: the raw samples travel beside it, and every arm runs `LC_ALL=C` (V-11 sorts `408` below `264,01` under a comma-decimal locale).
- Do not repeat a benchmarked transfer without cancelling it first: a second request for the same live selection is idempotently re-acked and emits no `transfer.incoming`.
- Do not drive the control plane in a tight loop: mutations are 4/s burst 8, and exceeding it drops the peer, not just the message.
- Do not time a browser pipeline from outside the page: Playwright's `expect` polls on a 100/250/500 ms grid and the grid becomes the number.
- Do not leave a relay socket on the default `binaryType`: every binary message then pays an `await blob.arrayBuffer()` (366 ms of a 630 ms 32 MiB transfer).
- Do not await one AEAD open per frame in a chain: webkit and firefox overlap concurrent opens 2.1-2.5x, chromium does not care, and order is kept by consuming the results, not by serializing the calls.
- Do not keep an optimization that measures inside the noise: the pre-opened part file read 87.03 against 86.32 MiB/s over five repetitions and was removed.
- Do not put a trickle-ICE message on the mutation token bucket: the gate then measures the bucket and not the candidate budget, and the handshake it protects is the thing it stalls.
- Do not let a monitor re-resolve a room key at deadline time: the deadline timer carries `Weak<WebTransferRoom>` plus the TransferId and AttemptId and acts only on an identity match (P-14, the same shape as the direct-carrier close monitor).
- Do not decide a fallback from the state alone or the attempt alone: `fallback_to_relay` checks `is_negotiating_direct() || ActiveDirect` AND `attempt_id == failed_attempt` under one lock, which is what makes "one fallback, one permit" structural rather than a race that usually goes the right way.
- Do not add a forwarded message type to `SERVER_TYPES` in Rust only: the JS mirror refuses an unknown server type, so the message is built, sent and then dropped by the page.
- Do not republish the same offer id in a second unit fixture: the room answers `OFFER_CHANGED` and the test fails for a reason that has nothing to do with what it measures.
- Do not close a transport right after the FINAL frame — not the DataChannel and, since 4.4, not the relay socket either. The FINAL frame is the end-of-stream marker on BOTH, and a close races the bytes still queued behind it: `bufferedAmount == 0` says the engine took the message, not that the peer read it (WebKit delivered 7 087 168 of 8 388 613 already written).
- Do not let a peer stay silent about a failed attempt because the other end reported it first: the recipient's verified ranges exist nowhere else, and exactly-once belongs in the ANSWER (`directFailed` returns `null` for an attempt already reported), never in the ordering.
- Do not assert in an e2e gate which end noticed a dead channel first, or which reason it carried: two engines' timers decide it and the assertion becomes a scheduler test.
- Do not infer "something is verified" from bytes received: hashing runs behind the wire, and under load an engine can hold two whole unverified chunks. A resume gate establishes the precondition (`receiverState().verifiedRanges`), it does not assume it.
- Do not treat a closed transport as a failed attempt: ask the transfer actor whether the attempt is still carrying, or every successful direct transfer ends by requesting a relay attempt nobody wants.
- Do not let a browser declare `transfer.direct_ready` before its own SDP step is done: the server refuses it and the refusal burns the attempt.
- Do not leave the Phase 3 relay e2e gates on the default path once direct is the default: they then measure the direct path under a relay name.
