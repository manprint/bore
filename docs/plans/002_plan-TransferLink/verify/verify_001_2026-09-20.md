## Executive summary

The command, file/ZIP streaming, TLS vhost integration and the existing regression suite build and run. The implementation was not releasable against the approved plan at the audit point. C01 fixed the source-vs-connection completion race, C02 fixed process-group ownership, C03 fixed terminal one-shot failure propagation, C04 fixed scoped task/HTTP shutdown ownership, C05 now applies manifest budgets while enumerating directories, C06 separates retryable TLS transport failures from permanent verification failures, C07 removes bearer URL components from scoped logs, C08 aligns the public label, adaptive carriers, timer-driven progress and README trust/outcome wording, and C09 makes Docker acceptance rebuild the current locked source while red-checking a stale static artifact. The remaining findings and mandatory acceptance measurements still require the later corrections below.

The already-published `v1.2.0-rc.6` contains this implementation. It should not be promoted as the stable release before V001 corrections and a fresh verify pass.

Verify mode changed no production code. Every open item below has an executable correction and regression-test requirement for `plan-execute-verify execute verify V001`.

## Findings

### V001-F01 — BLOCKER — Source completion wins before the HTTP connection outcome

- **Status:** **FIXED 2026-09-20** — `DownloadOutcome` records source completion as a candidate and commits it only after the Hyper connection succeeds; connection errors mark the one-shot failed. GET responses omit `Content-Length` so Hyper must poll the terminal source frame; HEAD retains the known size. Tests `source_completion_is_only_a_candidate_until_connection_success`, `transport_failure_wins_over_source_success`, `body_disconnect_wins_when_source_was_ready_to_complete`, and the 22-test Link integration suite pass.

- **Class:** divergent implementation; integrity/false-success risk.
- **Evidence:** `src/transfer_link/http.rs:654-670` marks the body complete, moves one-shot state to `Consumed` and logs `download completed` as soon as `SourceMessage::Complete` is polled. `serve_connection` only observes the Hyper connection future separately at `src/transfer_link/http.rs:227-248`; errors are merely logged at `:215-223`. The sized-file drop path also treats bytes handed to Hyper as fully sent at `:555-605`. GET files receive `Content-Length` through `build_file_response` (`:405-448`), so Hyper may stop polling at the declared boundary; a zero-byte response can finish before the asynchronous producer performs its final fingerprint validation.
- **Contract:** `phase_01.md:57-73` requires the HTTP connection outcome to take precedence; `phase_04.md:84-89` requires a later HTTP error to leave exec Failed; `phase_05.md:31-36` names `transport_failure_wins_over_source_success`.
- **Impact:** a receiver that disconnects after Hyper accepts the final frame can make A log success and consume a one-shot stream although B did not receive the full response. SHA-256 then describes producer bytes, not a successfully completed HTTP delivery.
- **Correction:** introduce one terminal outcome owner shared by body and connection supervisor. Producer completion records a candidate result; only successful completion of the HTTP connection commits `Completed`/`Consumed`. Any socket/connection error first or later commits Failed exactly once. Ensure empty and sized files cannot bypass final source validation through `Content-Length`. Add deterministic `body_disconnect_overrides_successful_exit`, `transport_failure_wins_over_source_success` and empty-file mutation tests at the real Hyper connection boundary.

### V001-F02 — BLOCKER — Body drop can abort the owner of exec process-group cleanup

- **Status:** **FIXED 2026-09-20** — `ProducerTaskOwner` keeps the producer task and cancellation token alive independently of the HTTP body. A connection error cancels the producer and `serve_connection` awaits its supervisor before returning; `MessageBodyState::drop` no longer aborts the owner. `terminate_child` runs TERM→bounded wait→KILL→reap, and non-`ESRCH` process-group errors are logged. The privileged gate now starts a foreground producer whose leader exits on TERM while a grandchild ignores TERM, disconnects a real GET, and proves both PIDs are gone before pass.

- **Class:** divergent implementation; process/resource leak risk.
- **Evidence before correction:** `MessageBodyState::drop` cancelled and immediately aborted the producer task, while the old privileged harness did not exercise a real GET disconnect with a TERM-ignoring grandchild.
- **Contract:** `phase_04.md:82-89` explicitly forbids keeping `Child`/PGID in a task that can disappear without teardown and says `kill_on_drop` is only a safety net.
- **Impact resolved:** a downloader disconnect now leaves the owner task alive long enough to terminate the owned process group, and the gate observes the cleanup externally.
- **Correction evidence:** C02 narrow Rust gates passed; `sudo -n scripts/transfer_link_privileged_test.sh cancel` passed with a real curl disconnect, leader/grandchild PID assertions, and bounded cleanup.

### V001-F03 — MAJOR — A failed stdin/exec transfer does not terminate the CLI

- **Status:** **FIXED 2026-09-20** — `OneShotState` now publishes a terminal failure signal through a `watch` channel. The CLI subscribes before registration, cancels and joins the supervisor on failure, and returns a nonzero error. The basic e2e gate now uses a FIFO producer, claims a real GET, interrupts curl after bytes arrive, asserts bore exits nonzero within seven seconds, and verifies the producer observes stdin closure.

- **Class:** divergent implementation and invalid acceptance test.
- **Evidence before correction:** `OneShotState::failed()` only stored an atomic status, and the old cancellation case started an infinite pipe without issuing a GET.
- **Contract:** D13 in `overview.md:39` and `phase_04.md:63-71` require a failed/interrupted consuming GET to terminate bore nonzero and release the external pipe.
- **Impact resolved:** a failed consuming GET now ends the one-shot CLI and closes its stdin; a new producer/link invocation is required for a retry.
- **Correction evidence:** C03 narrow Rust gates and `bash scripts/transfer_link_e2e.sh basic` passed with the real FIFO/GET disconnect oracle.

### V001-F04 — MAJOR — Scoped task bookkeeping grows for the lifetime of the link

- **Status:** **FIXED 2026-09-20** — scoped tasks now register abort handles in a keyed map and carry a `Weak<ClientScope>` RAII guard. The guard removes its own handle on task completion or abort, while shutdown snapshots only live handles. A 128-iteration unit confirms the count returns to zero after every completed task.

- **Class:** resource-bound invariant violation.
- **Evidence before correction:** every `ClientScope::spawn` appended an `AbortHandle` that stayed in a vector until final shutdown.
- **Contract:** I-9 in `overview.md:133` and `phase_02.md:29-35` require bounded task/resource ownership for a link that may serve unlimited sequential downloads.
- **Impact resolved:** completed connection churn no longer retains abort handles.
- **Correction evidence:** C04 client lifecycle unit passed with 128 completed scoped tasks and zero retained handles.

### V001-F05 — MAJOR — Manifest caps are applied after unbounded directory collection

- **Status:** **FIXED 2026-09-20** — directory enumeration receives the remaining global entry/path budgets and rejects the first child that would exceed them. Reserved entries include pending nodes, so nested directories cannot reset the cap. Validation enumeration is bounded as well. Unit tests cover zero entry and zero path-byte budgets before collection.

- **Class:** bounds/security violation.
- **Evidence:** `read_directory` collects every child and its owned name/path/fingerprint into `children`, sorts it, and allocates two more vectors at `src/transfer_link/manifest.rs:577-614`. Entry/name caps are enforced later while pending nodes are walked, not while this directory is enumerated.
- **Contract:** D10 in `overview.md:36` requires rejecting over 100,000 entries/32 MiB of names before publication; I-1/I-9 require bounded memory. `phase_03.md` assigns the limits to manifest construction.
- **Impact:** one hostile or accidental huge directory can consume memory well beyond the advertised manifest cap before rejection.
- **Correction evidence:** `ManifestBuilder::reserved_entries` and `path_bytes` are reserved during directory enumeration; `enumerate_directory` checks both budgets before pushing a child. Manifest unit tests and the Link suite pass with the narrow C05 gates.

### V001-F06 — MAJOR — Transient TLS handshake failures are classified as permanent verification failures

- **Status:** **FIXED 2026-09-20** — `ConnectFailure::TlsTransient` now covers the TLS timeout and socket I/O classes (including EOF/reset), while certificate, hostname and protocol/data errors remain `ConnectFailure::Tls`. Link attempt classification retries only the transient class and stops on verification failures. Transport and CLI unit tests plus both 22-test Link configurations pass.

- **Class:** divergent retry/error handling.
- **Evidence:** `src/transport.rs:204-209` wraps timeout, socket EOF and every TLS handshake error in `ConnectFailure::Tls`. `src/transfer_link_cli.rs:431-466` maps all of them to `TlsVerification` and stops permanently.
- **Contract:** `phase_02.md:49-52` makes explicit certificate/hostname verification permanent and I/O, timeout or control disconnection transient with cancellable backoff.
- **Impact before correction:** a transient handshake timeout or reset killed a published link rather than reconnecting with the same URL.
- **Correction evidence:** timeout/EOF/reset classification is tested at the transport boundary; the Link classifier test proves transient retry and permanent verification stop. Carrier-specific fault injection remains a broader acceptance gap covered by the existing T-LINK-TLS partial status.

### V001-F07 — MAJOR — Logs disclose the bearer components of the public URL

- **Status:** **FIXED 2026-09-20** — scoped Link logs now correlate with a monotonic process-local `session_id`; label, URL and filename are absent from the supervisor, client, QUIC, vhost and control-frame summaries. The basic e2e runs the client at `-v` and `-vv` and fails if stderr contains the generated host, full URL or filename.

- **Class:** security/privacy rule violation.
- **Evidence:** the generated label is logged by the Link supervisor (`src/transfer_link_cli.rs:264`) and generic vhost readiness (`src/client.rs:975`); `src/main.rs:1968-1975` logs both label and advertised filename. The vhost base domain is operator-known, so these fields reconstruct the bearer URL.
- **Contract:** D12 calls the URL a bearer credential (`overview.md:38`); `phase_02.md:68-70` authorizes one stdout URL and forbids token URL components in info/debug logs.
- **Impact before correction:** centralized logs or support bundles could grant download access for the life of the process.
- **Correction evidence:** scoped vhost readiness, QUIC carrier, server vhost and frame-summary logs redact bearer values; legacy unscoped vhost diagnostics remain available. The e2e stderr scan is green at both requested verbosity levels.

### V001-F08 — MAJOR — Phase 4.1 was closed without its mandatory transport and cleanup gates

- **Class:** missing implementation/evidence and stale state.
- **Evidence:** `STATE.md` records phase 4 and subphase 4.1 DONE while also recording T-LINK-DROP and the 100-cycle cleanup as NOT RUN. `phase_05.md:28-38` requires real direct QUIC, automatic fallback with UDP blocked for N=1/N=2, mid-download UDP loss for file/stdin/exec, and 100 cleanup cycles. The phase criterion at `:113-115` disallows a mandatory non-run gate.
- **Impact:** the exact false-success and cleanup paths implicated by F01/F02 have no live fault oracle; `--relay-only` is not evidence of automatic fallback.
- **Correction:** implement and run the netns cases exactly as specified, with kernel/server path evidence, hashes, nonzero interrupted clients, one-shot no-replay, process cleanup and FD/registry baselines. Red-check each oracle. Do not use the present `relay_only=true` log as proof of automatic UDP-blocked fallback or the actual data path.

### V001-F09 — MAJOR — Phase 4.2 was closed without throughput, 15 GiB or no-spool evidence

- **Class:** missing acceptance evidence and stale state.
- **Evidence:** `STATE.md` records subphase 4.2 and phase 4 DONE but T-LINK-PERF NOT RUN and the 15 GiB case absent. `phase_05.md:46-56` requires three-run medians versus equivalent vhost, ≥90% raw throughput, ≤100 ms added TTFB, stdin ≥15 GiB with slow/fast sinks, RSS thresholds and live no-spool observation.
- **Impact:** the user’s maximum-bandwidth and low-disk requirements remain unverified; a 4 GiB sparse ZIP test is not the stdin 15 GiB streaming case.
- **Correction:** add a reproducible evidence script/file, build current release, run the specified transport/source/concurrency matrix and record raw measurements, environment and medians. Keep a failing threshold as a failed gate rather than weakening it.

### V001-F10 — MAJOR — HTTP supervisor can detach its task on shutdown timeout

- **Status:** **FIXED 2026-09-20** — the timeout path now borrows the HTTP `JoinHandle`, calls `abort`, and awaits the same handle through `abort_and_join`; it no longer drops a timed-out handle. A unit task with a Drop marker proves the task is cancelled and joined.

- **Class:** task ownership violation.
- **Evidence before correction:** the old timeout passed the `JoinHandle` by value to `timeout`, detaching it on elapsed timeout.
- **Contract:** `phase_02.md:53-54` and I-9 require old scope/listener/source tasks to be fully stopped within a budget before return/reconnect.
- **Impact resolved:** the shutdown path retains ownership until the HTTP task has acknowledged abort or the bounded second wait is logged as a failure.
- **Correction evidence:** C04 abort/join unit passed with a non-cooperative task.

### V001-F11 — MINOR — Generated label omits the approved `transfer-` prefix

- **Status:** **FIXED 2026-09-20** — `generate_link_label` now emits `transfer-` plus a 16-character lowercase base-36 suffix; the unit test checks the exact prefix and suffix alphabet, and the basic HTTPS harness accepts the resulting hostname.

- **Class:** CLI/public URL contract divergence.
- **Evidence:** D2 and examples require `transfer-<16 chars>` (`overview.md:14,28`; README `:2261-2265`). `generate_link_label` returns only the 16 random characters (`src/transfer_link_cli.rs:396-411`) and that value is passed directly as the vhost label (`:139`).
- **Correction:** generate the random ID separately and form `transfer-{id}` for registration; validate wildcard length and update tests to assert the exact host label.

### V001-F12 — MINOR — `--carriers 0` auto mode is rejected by the Link CLI

- **Status:** **FIXED 2026-09-20** — the Link parser accepts `0..=32`, retains `1` as the default, and has a parser regression for `--carriers 0`; the existing client adaptive path receives the value unchanged.

- **Class:** CLI contract divergence.
- **Evidence:** `overview.md:61` and `phase_02.md:65` define `0..32`, where 0 is existing auto mode; `Client` still handles 0 at `src/client.rs:977-983`. Clap restricts Link to `1..=32` at `src/main.rs:1413-1415`, and README repeats that narrower range.
- **Correction:** allow 0 in the parser and document/test its auto semantics, or record an explicit approved plan deviation before changing the contract.

### V001-F13 — MINOR — Progress is data-triggered and omits the active count

- **Status:** **FIXED 2026-09-20** — each active body selects between source messages and a periodic timer, reports `active_downloads`, and decrements the gauge on every body drop; the no-data timer unit proves a progress frame without a source chunk.

- **Class:** observability divergence.
- **Evidence:** progress is emitted only inside `SourceMessage::Data` handling when elapsed time exceeds the interval (`src/transfer_link/http.rs:635-650`). A stalled producer/consumer emits no periodic state, and the fields omit the required active count.
- **Contract:** `phase_02.md:68-69` and `phase_05.md:51-54` require interval-driven progress, active count and useful stalled-transfer diagnostics.
- **Correction:** drive reporting from a timer/select branch independent of chunks, snapshot atomics without blocking the data path, include active count, and test a no-data interval plus a slow consumer.

### V001-F14 — MAJOR — Docker acceptance may test a stale binary

- **Status:** **FIXED 2026-09-20** — the Docker harness removes and rebuilds the locked current target before every run, checks static linkage, and deliberately installs a valid aged static artifact before rebuilding; the mtime oracle fails if the artifact is reused.

- **Class:** invalid/non-hermetic gate.
- **Evidence:** `scripts/transfer_link_container_test.sh:20-26` rebuilds only if the static executable is absent or not static. An executable built from any older revision is silently reused despite the comment claiming the current binary.
- **Contract:** `STATE.md` §3 and `phase_05.md:46` require building the current revision before acceptance/performance runs.
- **Impact:** G-DOCKER can pass while the checked-out source would fail inside the image.
- **Correction:** always build the locked current source, or stamp and verify source/Cargo hashes before reuse. Add a gate self-test that places an older valid static binary and proves a rebuild occurs.

### V001-F15 — MINOR — README contains trust and transfer-outcome inaccuracies

- **Status:** **FIXED 2026-09-20** — README now documents bundled WebPKI roots plus additive PEM trust, timer-based progress and active count, source/HTTP completion semantics, and nonzero stdin failure with producer restart.

- **Class:** documentation divergence.
- **Evidence:** README `:2317` says `--ca-cert` extends “system roots”; `src/transport.rs:251-266` initializes `webpki_roots::TLS_SERVER_ROOTS` and then adds the PEM. No operating-system root store is loaded. README `:2342` says all bytes were sent to the HTTP peer although F01 only counts bytes supplied to Hyper; `:2357` describes 410 after interrupted stdin although the approved lifecycle requires bore to exit nonzero; the foreground/no-daemon exec restriction from `phase_04.md:87` is absent.
- **Correction:** document bundled WebPKI roots plus the additive PEM, sender-side connection semantics after F01 is fixed, nonzero stdin failure/restart, and the foreground exec contract. Keep hostname verification wording and avoid claiming durable receipt on B.
