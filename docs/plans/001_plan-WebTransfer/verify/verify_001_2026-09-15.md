## Findings

### V001-F01 — An identical offer replay can lose idempotency at a saturated cap
- **Status:** `FIXED` — 2026-09-15 by `execute verify V001-C1`; saturated per-peer/room/global caps now preserve identical replay and `OFFER_CHANGED`, proved by `identical_publish_is_idempotent_at_saturated_caps`.
- **Severity:** `MAJOR`
- **Category:** divergent
- **Where:** `src/web_transfer.rs:1362` — plan ref `phase_03.md § 2.3`
- **Expected:** “Publish identical offer ID/manifest/MAC idempotently; same ID with any different byte returns `OFFER_CHANGED`.”
- **Actual:** `publish_offer` reserves global metadata and rejects the per-peer/per-room caps before looking up the existing OfferId; once any cap is full, an identical retry can return `LIMIT_EXCEEDED`, and a changed retry can do the same instead of `OFFER_CHANGED`.
- **Impact:** a lost acknowledgement is not safely replayable at precisely the load boundary where retry safety matters; the wire contract becomes dependent on unrelated capacity.
- **Correction:** authenticate the peer and resolve an existing OfferId before any new-offer reservation/cap path, preserving `OFFER_CHANGED` for every non-identical collision; add a saturated-cap regression.

### V001-F02 — Room revisions wrap instead of failing checked
- **Status:** `FIXED` — 2026-09-15 by `execute verify V001-C2`, lifecycle-completed in C5 final review; all mutation paths use checked revision arithmetic, while exhausted RAII cleanup removes/destroys/cancels the room and emits `revision-exhausted` instead of a wrapped incremental. `room_revision_overflow_never_wraps_or_leaks_state` proves rollback, accounting, registry removal, destruction and cancellation.
- **Severity:** `MAJOR`
- **Category:** divergent
- **Where:** `src/web_transfer.rs:1308`, `:1344`, `:1426`, `:1474`, `:2400`, `:2408` — plan ref `phase_03.md § 2.2`
- **Expected:** “Events carry monotonically checked room revision.”
- **Actual:** all join/rename/publish/withdraw/peer-cleanup increments use `wrapping_add(1)`, so `u64::MAX` produces revision 0.
- **Impact:** wrap destroys snapshot/event ordering and can make clients accept stale state as current.
- **Correction:** use one checked revision primitive; operations that can reject must do so before mutation, while infallible RAII cleanup must remove resources and terminate incremental delivery safely rather than publish a wrapped revision; add overflow rollback/cleanup tests.

### V001-F03 — Malformed bracketed Host authorities can match the configured origin
- **Status:** `FIXED` — 2026-09-15 by `execute verify V001-C3`; authority parsing is fallible and validates exact bracket/IPv6/suffix/port syntax, proved by the expanded `web_route_requires_configured_authority` matrix.
- **Severity:** `MAJOR`
- **Category:** rule-violation
- **Where:** `src/web_transfer_http.rs:165` — plan ref `phase_03.md § 2.1` and `D10`
- **Expected:** routing intercepts only the exact configured authority, with default-port normalization.
- **Actual:** `split_host_port` discards any invalid suffix after `]`; values such as `[::1]:abc`, `[::1]:0`, and `[::1]evil` normalize to the same host/no-port shape as a valid authority.
- **Impact:** the same-origin routing boundary accepts syntactically invalid authorities that the plan requires it to reject exactly.
- **Correction:** make authority splitting fallible and validate brackets, IPv6 literal, suffix and port `1..=65535`; reject malformed input before comparison and add IPv6 authority regressions.

### V001-F04 — Bracketed STUN targets bypass host/port validation
- **Status:** `FIXED` — 2026-09-15 by `execute verify V001-C4`; one strict parser now serves direct ICE resolution and server flags, proved by the valid DNS/IPv4/bracketed-IPv6 and malformed target matrices.
- **Severity:** `MAJOR`
- **Category:** divergent
- **Where:** `src/web_transfer.rs:2219` — plan ref `phase_01.md § 0.1`
- **Expected:** custom entries must be `stun:HOST[:PORT]` with a present host and, when supplied, a numeric port.
- **Actual:** the bracketed branch accepts empty/malformed hosts and invalid suffixes/ports, including `stun:[]`, `stun:[::1]:0`, `stun:[::1]:abc`, and `stun:[::1]:65536`.
- **Impact:** invalid startup configuration is accepted and then handed to browsers, moving a deterministic configuration error into opaque ICE failures.
- **Correction:** validate bracketed IPv6 and its exact optional port syntax, reject URI delimiters/whitespace and ambiguous bare IPv6, and add valid/invalid matrix tests.
